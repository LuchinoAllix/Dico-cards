# Dico-cards

An offline, multilingual dictionary with spaced-repetition quizzes, built with React Native (Expo) and TypeScript.

Look up a word, save it, organize saved words into collections, and quiz yourself with flashcards. Everything runs on the device: the dictionaries are bundled with the app, and your saved words never leave your phone. No internet connection is needed.

## Features

- **Offline dictionaries** for several languages (currently French, English and Italian), searchable as you type, with accent-insensitive prefix search.
- **Word detail** with pronunciation (IPA), meanings grouped by part of speech, and examples.
- **Saving and collections.** Save any word, and put it in as many collections as you like. A virtual "Recent" collection lists words saved in the last N days (configurable).
- **Spaced-repetition quiz** using the FSRS algorithm, with two modes: *word → meaning* and *meaning → word*. Each mode keeps its own schedule.
- **Word of the day** for each language on the home screen.
- **Settings:** the "Recent" duration, target retention, and the number of words per study session.

| Purpose | Tool |
|---|---|

## How it works

### Architecture

The code is organized in layers, and each layer only talks to the one below it:

```
screens (app/)
   ↓ call
data layer (src/db/)  ← the only code that touches SQLite
   ↓ read/write
dictionary databases (read-only)    user.db (read/write)
```

Screens never run SQL. They call small functions such as `searchWords`, `saveWord` or `getDueWords`. This is why the dictionary storage could move from JSON files to SQLite without changing a single screen.

### Two separate databases

- **Dictionary databases** (`assets/dictionaries/<lang>.db`): one per language, read-only, generated by a script. They are bundled with the app and copied to the phone's storage on first launch.
- **`user.db`**: created on the device. It holds everything that belongs to the user. Keeping it separate means a dictionary can be replaced or updated without touching anyone's saved words.

### Dictionaries

Each dictionary has one table, `entries`, with one row per headword:

| Column | Content |
|---|---|
| `id` | `<language>:<headword>`, for example `fr:gratis` |
| `key` | the headword lowercased and stripped of accents, indexed for search |
| `headword` | the word as written |
| `pronunciation` | first IPA transcription found, if any |
| `meanings` | JSON text: a list of `{ partOfSpeech, definitions[], examples[]? }` |

A `meta` table stores the language, the build date and the entry count.

**Search** is a range query on the indexed `key` column ("starts with"), so it stays fast on hundreds of thousands of entries. The typed text is normalized the same way as the keys, so `ecole` finds `école`.

**The registry** (`src/db/dictionaries.ts`) lists the available dictionaries. Adding a language means adding one line there. Each entry has a `version`: when a dictionary is rebuilt, bumping its version makes the app replace the copy stored on the phone.

### User data

`user.db` contains:

| Table | Purpose |
|---|---|
| `saved_words` | one row per saved word (id, language, headword, date saved) |
| `collections` | user collections, unique per language |
| `collection_words` | links words to collections (many-to-many, so a word can be in several) |
| `card_states` | spaced-repetition state, one row per word **and quiz mode** |

Rules built into the schema:
- Un-saving a word removes it from every collection and deletes its schedules (`ON DELETE CASCADE`).
- Deleting a collection never deletes its words.
- "Recent" is **not** stored. It is a query: saved words whose date is within the last N days.

**Migrations** use SQLite's `PRAGMA user_version`. Each schema change is a new `if (version < N)` block in `src/db/userDb.ts`, so existing users' data is upgraded instead of reset. Never edit a migration that has already shipped; add a new one.

| Version | Change |
|---|---|
| 1 | `saved_words`, `collections`, `collection_words` |
| 2 | scheduling columns on `saved_words` (now superseded, unused) |
| 3 | `card_states`: one schedule per word and quiz mode |
| 4 | collections become per-language |

### Languages

The active language is kept in a small Zustand store (`src/state/language.ts`) and saved in the settings store, so the app reopens in the language you left it in. Saved words, collections, Recent and the quiz are all filtered by the active language, so a study session never mixes languages. The only exception is the home screen's "Recent words" button, which lists recent words from all languages.

### Quiz and scheduling

- The scheduling algorithm is **FSRS** through `ts-fsrs`. After you reveal an answer, you rate it *Again / Hard / Good / Easy*, and the library computes the next review date. The interval each button would give is shown under it.
- The quiz works on a **source** (Recent, all saved words, or one collection) and a **mode**.
- A session contains the due words of that source, reviews first and new words after, capped by the "words per session" setting.
- Answering *Again* puts the word back at the end of the current session.
- Each mode has its own schedule, because recognizing a word and recalling it from its meaning are different skills.
- The target retention setting changes how long the intervals are.

**Quiz modes are pluggable.** A mode is a small card component that receives `{ entry, revealed }` and draws the front and the back. The session screen is generic and handles the queue, the grading and the scheduling.

### Word of the day

Computed, not stored: a hash of the language and the current date picks a row number, so the same word shows all day and changes at midnight.

Folder names in parentheses, like `(tabs)`, group screens without changing the URL. Brackets, like `[id]`, mark a dynamic route.

## Getting started

### Requirements

- Node.js 22.13 or newer (the dictionary script uses Node's built-in SQLite)
- The **Expo Go** app on your phone, for development

### Install and run

```bash
npm install
npx expo start
```

Scan the QR code with Expo Go. Your phone and computer must be on the same network (or use `npx expo start --tunnel`). If you see an old version of the app, restart with `npx expo start --clear`.

### The dictionaries are not in the repository

The `.db` files are too large for Git, so a fresh clone must build them first (see below). The app will not start until the files listed in `src/db/dictionaries.ts` exist.

## Building the dictionaries

Dictionary data comes from [kaikki.org](https://kaikki.org), which publishes Wiktionary as machine-readable JSONL files (one entry per line, one part of speech per entry).

1. Download the JSONL file of a language from kaikki.org and put it in `raw/`. These files are very large (several GB for the biggest). For a quick test, only keep the first lines of the file.
2. Build the database:

   ```bash
   node scripts/build-dictionary-db.mjs raw/<file>.jsonl --lang fr
   ```

   The result is written to `assets/dictionaries/fr.db`. The `--lang` code must match the one in the registry, because it becomes the prefix of every word id.

What the script does:
- streams the file line by line, so memory stays low;
- skips inflected forms (plurals, conjugations), entries without a definition, proper names, prefixes, suffixes and symbols (the list is at the top of the script);
- groups the entries of a word, so one headword has several meanings;
- keeps the first pronunciation and up to 3 examples per meaning;
- writes the indexed SQLite file.

`scripts/build-dictionary.mjs` is the lighter variant that produces a small JSON file with the first N words. It is handy for testing the pipeline.

**Important:** the `normalize` function exists in both the script and `src/db/search.ts`, and the two **must stay identical**, otherwise searches silently miss words.

After rebuilding a dictionary, bump its `version` in `src/db/dictionaries.ts`, so installed apps replace their copy.

## Adding a language

1. Download the kaikki.org file and build the database with `--lang <code>`.
2. Check the output: other Wiktionary editions tag inflected forms differently, so the form-of filter in the script may need adjusting.
3. Add one entry to `DICTIONARIES` in `src/db/dictionaries.ts`.

The language picker, the home screen's word of the day and every other screen pick it up automatically.

## Adding a quiz mode

1. Add its id to `QuizModeId` in `src/quiz/types.ts`.
2. Write a card component in `src/components/cards/` that takes `{ entry, revealed }`.
3. Add one entry to `MODES` in `src/quiz/modes.ts`.

The mode picker, the due counts, the scheduling and the session screen need no change. Modes that grade themselves (multiple choice, typed answer) will need a small extension: the card would report correct or wrong, and the session screen would hide the four rating buttons.

## Installing on a phone

Build an Android APK with EAS and install it directly, without any store:

```bash
npm install -g eas-cli
eas login
eas build --platform android --profile preview
```

The `preview` profile in `eas.json` must use `"buildType": "apk"`. EAS uploads the project and **skips what `.gitignore` excludes**, which would remove the dictionaries, so the project has a `.easignore` file that replaces it (and still excludes `raw/` and `node_modules/`).

The installed app has its own storage, separate from Expo Go. Reinstalling a newer build over it keeps your data, but uninstalling deletes everything.

## Development notes

- Check types with `npx tsc --noEmit`. Expo Router generates typed routes, so after adding a screen, restart with `npx expo start --clear` so the new route is recognized.
- Test on a real device or emulator. `expo-sqlite` is not reliable in the browser.
- Jest (`jest-expo`) is installed. The scheduling logic is the part most worth testing, since it doesn't need a database.

## Known limitations and roadmap

- **No backup yet.** Saved words, collections and progress exist only on the device. Export/import of `user.db` data as JSON is planned.
- **App size.** The dictionaries are bundled, so the app is as large as they are. For more languages, the dictionaries should be downloaded on demand from a hosted file.
- **No sync between devices.** Syncing would need unique ids, update timestamps and deletion markers in the user data model before any server work.
- **More quiz modes:** multiple choice, typed answer, fill in the blank.
- **Stats and reminders:** a review log, streaks, and daily notifications.
- Colors are hard-coded for a light theme. Dark mode needs a theming pass.
